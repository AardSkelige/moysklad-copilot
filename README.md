# moysklad-copilot

Telegram-бот — корпоративный ассистент поверх [МойСклад](https://www.moysklad.ru) для небольшой производственной компании. Автоматизирует финансовый учёт, непрерывно аудирует складские и денежные документы с помощью LLM и управляет производственными заданиями голосом.

Работает в проде: единственный оператор — владелец компании, бот заменяет ему ручные проверки учёта, который ведут несколько сотрудников под одним аккаунтом МойСклад.

## Модули

### 💰 Финансы
- Создание входящих/исходящих платежей и ПКО/РКО прямо в МойСклад (без локальной копии — источник истины один)
- Категории операций с привязкой к статьям расходов МойСклад, синхронизация в одну сторону
- Экспорт операций за период в Excel

### 🔍 Аудит учёта
Двухслойная архитектура: **детерминированные детекторы + LLM-аналитик**.

- 17 проверок собирают сигналы с фактами из API: дубли платежей, нулевые цены в приёмках, отклонения оприходований от FIFO, поздние правки проведённых документов, зависшие черновики, отрицательные остатки, балансы контрагентов (взаиморасчёты считаются вручную — тариф не даёт отчёт), расхождения заказ/приёмка и др.
- LLM выносит вердикт по каждому сигналу — «проблема / норма / спросить человека» — с объяснением и вариантами исправления. Код не решает нюансные случаи сам.
- Диалоговый агент по находке: владелец обсуждает проблему, агент смотрит документы и историю изменений через tools, готовит исправление — применяется только после кнопки-подтверждения.
- Инкрементальные прогоны по расписанию + ночной полный скан (APScheduler).

### 📝 Ревью комментариев
LLM приводит комментарии документов к корпоративному стандарту («Имя: что сделано, точка в конце»), исправляет опечатки по словарю предметки, определяет вероятного автора по зоне ответственности. Владельцу — карточки «текущий / предлагаемый» с кнопками, правка пишется в МойСклад сразу. Отдельные промпты для отгрузок (перенос фактов в связанный заказ) и финансовых документов (назначение платежа + комментарий).

### 🏭 Производство
Агент создаёт и правит производственные задания голосом (Groq Whisper) или текстом: «сделай 40 шампуней», «переведи 305 в готово». Цикл LLM ↔ tools с превью и подтверждением перед записью.

## Архитектура

```
core/           конфиг (.env), модели БД, логгер
handlers/       aiogram-роутеры: finance / audit / production
services/       бизнес-логика; audit/checks/ — детекторы, analyst — LLM-слой
integrations/   клиенты МойСклад API (base + доменные), Excel
shared/         клавиатуры, FSM-состояния, константы, session_scope
```

Ключевые решения:

- **Engine vs knowledge.** Код промптов — в репозитории, бизнес-контекст компании (команда, словарь предметки, правила маршрутизации) — в `services/audit/team_context_local.py` вне git. В репозитории лежат обезличенные значения-примеры, бот работоспособен и без локального файла.
- **LLM предлагает — человек подтверждает.** Ни одна запись в МойСклад не происходит без явной кнопки владельца.
- **Деньги — только целые копейки** (INTEGER), рубли — только на отображении.
- **Операции живут в МойСклад**, локальная SQLite хранит только справочник категорий.

## Стек

Python 3.12 · aiogram 3 · SQLAlchemy 2 (async SQLite) · aiohttp · APScheduler · DeepSeek API (OpenAI-совместимый клиент) · Groq Whisper · openpyxl · Docker

## Запуск

```bash
cp .env.example .env          # заполнить токены и ID
pip install -r requirements.txt
python main.py                # схема БД создаётся автоматически
```

Docker: `docker compose up -d`. Деплой на сервер: `./deploy.sh` (адрес — в `DEPLOY_SERVER`).

## Тесты

```bash
pytest tests/unit/ -v          # 177 тестов
pytest tests/unit/ -m audit    # по маркерам: fsm, finance, validation, access, audit
```

FSM-workflow, детекторы аудита на канированных ответах API, ревью комментариев с фейковым LLM, парсинг сумм, access-middleware.
